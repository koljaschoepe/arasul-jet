Plan 013 — Der Workspace wird eine echte IDE + Flow-Plattform

Aus dem Frontend-Review vom 27.07.2026 + 3 Interview-Runden · Branch feat/013-ide-flow-plattform · 11 Batches · ein Deploy am Ende, dann Jetson-Live-Verify.

Leitbild

Arasul soll sich wie Cursor / VS Code anfühlen: eine konsistente Entwickler-Oberfläche, in der „Flows" (heute „Skills") als deterministisch orchestrierte, wartbare Schritt-Ketten gebaut, per Chat/Zeitplan/HTTP ausgelöst und deren Ordner mit GitHub synchronisiert werden. Der Chat ist die ausführende Ebene, nicht nur ein Frage-Antwort-Fenster. Durchgehendes Branding mit dem blauen Vogel-Maskottchen (zwinkert). Läuft weiter voll lokal & DSGVO-konform auf dem Jetson.

Querschnitt-Risiken

  • Geteilte Dateien (workspaceStore.ts, ActivityBar.tsx, index.css, TabContent.tsx) werden von mehreren Batches berührt → sequenziell bearbeiten, nicht parallel, um Konflikte zu vermeiden.
  • Tiefe Umbenennung (B6) ist die riskanteste Fläche: Ordner + DB + Mounts + Env gemeinsam; On-Disk-Migration bestehender Flows auf dem Gerät zwingend vor dem Start.
  • Ein Deploy am Ende = spätes Feedback; deshalb lokal je Batch tsc/Build/Tests grün halten und am Ende gründlich live prüfen.
  • Frontend-CI ist bewusst advisory (Auto-Merge) — nicht auf blockierend umstellen.
  • Jetson-Git-Repo hat bekannte Objekt-Korruption: vor Deploy receive.denyCurrentBranch=updateInstead prüfen + gc.log löschen.
