## Was die Abnahme misst

`scripts/test/rollen-abnahme.sh` gegen `https://localhost:8443`: legt einen
Admin und einen Mitarbeiter an, meldet beide an (den Mitarbeiter per E-Mail),
ruft jede der 145 Admin-Routen mit dem Mitarbeiter auf und erwartet 403, prüft
fünf Mitarbeiter-Routen auf 200 und vier Admin-Routen mit dem zweiten Admin
auf 200, löscht beide Benutzer wieder. Die Liste der Admin-Routen kommt aus
`scripts/test/rollenregeln.py --json`, also aus dem Code, nicht aus einer
Abschrift.

Im Testlauf: `rollenregeln.py` ist rot, sobald eine montierte Route weder
`requireRole` noch `requireApiKey` trägt und nicht mit Grund in `OEFFENTLICH`
steht (neun Routen: Login, Setup, Sitzungsprobe, Forward-Auth, Herzschlag,
Setup-Status, Passwortregeln, Selbstheilungs-Webhook).

## Entscheidungen unterwegs

| Entscheidung                                   | Warum                                                                                                                                                                                                             |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `requireAdmin` ersetzt, nicht ergänzt          | Zwei Bausteine für dieselbe Prüfung wären doppelt; `requireRole('admin')` sagt an der Route, was gilt.                                                                                                            |
| `/api/benutzer` neu                            | Die Abnahme muss zwei Benutzer über HTTP anlegen und löschen; ohne Verwaltung gäbe es die zweite Rolle nur per `psql`. Die Löschung ist dieselbe wie `DELETE /api/gdpr/me`, aus der Route in den Service gezogen. |
| API-Schlüssel verwalten ist Admin              | Ein Schlüssel öffnet die externe API; die Vorgabe „bleibt wie sie ist" betrifft die Routen MIT Schlüssel, die sind unverändert.                                                                                   |
| `/api/apps` ist Admin                          | Die Freigabe („seine freigegebenen Apps") gibt es noch nicht; bis dahin gilt die Regel: nicht ausdrücklich Mitarbeiter heißt 403. Kommt mit den C-Phasen zum App-Modell.                                          |
| `GET /api/gdpr/export` auch Mitarbeiter        | Die Auskunft (Art. 15) betrifft die eigenen Daten; sie war nur deshalb Admin, weil es nur den einen gab.                                                                                                          |
| Login auch per E-Mail                          | „Mitarbeiter melden sich mit E-Mail und Passwort an" (Vision). Sperre und Anmeldeprotokoll laufen weiter über den eingegebenen Namen.                                                                             |
| Ein Benutzer löschen räumt seine API-Schlüssel | Der FK stünde sonst auf NULL (Migration 037), und ein Schlüssel ohne Eigentümer hielte die externe API offen.                                                                                                     |
